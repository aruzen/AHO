# 未実装箇所レポート

作成日: 2026-08-08

## 調査範囲

`AHO`, `AHOLi`, `VSLi`, `Dev`, `Test` と主要な CMake 設定を静的に確認した。主に `TODO`, `FIXME`, `Implement me`、空実装、戻り値未設定、エラー時に不完全な状態を返す処理を対象にした。

このレポートは実装ギャップの洗い出しであり、全 API の仕様レビューや Vulkan 実行時検証までは含まない。

## 優先度高

### AHO リソースバッファの未完成

対象:

- `AHOLi/AHO/include/AHO/resource/buffer.hpp`

状態:

- `Buffer<BufferType::General>` は `new char[size]` で領域を確保しているが、デストラクタ、コピー/ムーブ制御、`m_size` の初期化がない。
- `Buffer<BufferType::GPUFriendly>::data()` と `size()` が戻り値を返していない。
- `Buffer<BufferType::GPUFriendly>` のコンストラクタが空実装。
- `Buffer<BufferType::OnGPU>` はコンストラクタ宣言が private 側にあり、実装も見えない。

影響:

- `General::size()` が未初期化値を返す。
- `GPUFriendly` を使うコードは未定義動作またはコンパイル警告/エラーの原因になる。
- 生ポインタ管理のため、現状のままだとリークや二重解放を起こしやすい。

次の作業:

- `General` は `std::vector<char>` または `std::unique_ptr<char[]>` に寄せる。
- `GPUFriendly` と `OnGPU` の責務を決め、未実装 API を削るか実装する。
- コピー不可/ムーブ可などの所有権ルールを明示する。

### AHO 型安全パイプライン構想の未完成

対象:

- `AHOLi/AHO/include/AHO/pipeline/pipeline.hpp`
- `VSLi/VSL/include/VSL/utils/typed_safe_resource.hpp`

状態:

- `ComputePipeline` / `GraphicPipeline` は現在タグ型に近く、実際の VSL パイプライン種別を型で保証していない。
- `Pipeline<>` factory の TODO が残っており、標準パイプライン生成の入口が未完成。
- `PushConstant` のサイズ計算に FIXME がある。
- `TypedVertexInput<...>::injection()` が空実装。

影響:

- コンパイル時に保証したいパイプライン種別、頂点入力、Push Constant の整合性がまだ保証されない。
- C++23 の型安全設計を活かす中心部分が未完成で、利用側のミスを実行時まで持ち越す。

次の作業:

- `Pipeline<Definitions...>` が生成する VSL pipeline layout と実 pipeline の対応仕様を固める。
- `TypedVertexInput::injection()` で binding/attribute description を確実に反映する。
- Push Constant の合計サイズ、offset、shader stage の検証を追加する。

### Vulkan frame/present 処理の image index 扱い

対象:

- `VSLi/VSL/src/vulkan/phase.cpp`

状態:

- `acquireNextImageKHR()` の result check が TODO/FIXME のまま。
- `DefaultPhase::submit()` で acquire した `imageIndex` ではなく `manager.getCurrentBufferIdx()` を present に渡している。
- コメント上も `acquireNextImageKHR` 周辺の不具合が示されている。

影響:

- swapchain image index と command buffer frame index が一致しない環境で誤った画像を present する可能性がある。
- resize、out-of-date、suboptimal の扱いが不完全。

次の作業:

- acquire 結果の `vk::Result` を見て `eSuccess`, `eSuboptimalKHR`, `eErrorOutOfDateKHR` を分岐する。
- present には acquire で得た `imageIndex` を渡す。
- frame index と swapchain image index の命名と責務を分離する。

### GLFW/Vulkan 初期化失敗時の不完全状態

対象:

- `VSLi/VSL/src/window.cpp`
- `VSLi/VSL/src/vulkan/surface.cpp`

状態:

- GLFW 初期化失敗時、コンストラクタ内でログ出力して `return` している。
- surface 作成失敗時も `_data` を作った後に `return` している。

影響:

- 呼び出し側からは「構築済みのように見えるが内部ハンドルが無効」という状態になりやすい。
- 後続の destructor や Vulkan 操作で null/未初期化ハンドルを触る可能性がある。

次の作業:

- 失敗時は例外を投げるか、factory 関数で `std::expected` 相当の戻り値にする。
- destructor 側で null/無効ハンドルを安全に扱う。

## まとめ

最初に手を付けるべきなのは次の 4 点。

1. `AHO/resource/buffer.hpp` の未定義動作を解消する。
2. `phase.cpp` の acquire/present index と swapchain recreate 処理を直す。
3. `window.cpp` と `surface.cpp` の初期化失敗時の扱いを例外または明示的な失敗値にする。
4. 型安全 pipeline の範囲を決め、`TypedVertexInput::injection()` と Push Constant 検証を実装する。

この順に進めると、実行時クラッシュにつながる箇所を先に減らし、その後に AHO 側の設計上の価値である型安全 pipeline を固められる。
